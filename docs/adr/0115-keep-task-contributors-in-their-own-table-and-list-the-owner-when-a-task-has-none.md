# ADR 0115: Keep task contributors in their own table, and list the owner when a task has none

![Active][status]

## Context

Spec #616 records who did the work on each task: the owner, an agent with the model it ran on, or both. Nothing on a
task says so today. Tags name the kind of work, `task_sources` names the issue a task came from, and most tasks close
when the issue sync sees their issue closed, so `completed_at` says nothing about who did the work.

Contributors come from the admin task editor, from an agent through `save_task` or the API, and from the commit
sync, which reads `Co-Authored-By` trailers on commits that `Closes #N` a synced task. Claude's trailer names the
model, as in `Claude Opus 5.5`, but not the tool that ran it.

[ADR 0065][0065] makes tags a task's only labels. [ADR 0077][0077] tags a task from its labels only on import, so a
tag the owner removes stays off. [ADR 0015][0015] types a closed set as an enum and a format as a domain, and
[ADR 0017][0017] keeps rules over stored state in Postgres. #616 fills in no task closed before it ships.

## Decision

**Contributors live in a `task_contributors` table in the `tasks` slice.** #618 adds it in migration
`20261006000618`:

```sql
CREATE TYPE contributor_kind AS ENUM ('owner', 'agent');

CREATE DOMAIN contributor_slug AS text
  CHECK (VALUE ~ '^[a-z0-9]+([.-][a-z0-9]+)*$' AND length(VALUE) <= 64);

CREATE TABLE task_contributors (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  task_id integer NOT NULL REFERENCES tasks (id) ON DELETE CASCADE,
  kind contributor_kind NOT NULL,
  agent contributor_slug,
  model contributor_slug,
  created_at timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT task_contributors_kind_check
    CHECK (num_nonnulls(agent, model) = CASE kind WHEN 'owner' THEN 0 ELSE 2 END)
);

CREATE UNIQUE INDEX task_contributors_task_id_agent_model_index
  ON task_contributors (task_id, agent, model) NULLS NOT DISTINCT;
```

An owner row has no agent and no model, and an agent row has both. The unique index allows one owner row per task
and one row per agent and model. Rows never change: saving a task's contributors deletes the old rows and inserts the
new ones, so the table has no `updated_at`. `Blog::Types` gains the enum's Ruby twin and a type for the domain.

**Agents and models are text in a domain, not an enum or a table.** An agent is a slug such as `claude-code`. A model
is the model's own id, such as `claude-opus-5-5`. Views may word them for reading, but filters match the stored
slug.

**No row means the owner.** A task with no contributor rows lists the owner. Nothing stores an owner row on create,
and the default resolves on read: `read_task`, the API and the admin show `[{kind: "owner"}]` for such a task.
Filtering by the owner matches a task with an owner row or with no rows at all, in `Tasks::Relations::Tasks#narrowed`
(#622) and in the rebuilt `review_tasks` and `activities` views (#623).

**Adding an agent takes the owner off a task that listed the owner by default.** Once a task holds an agent row, it
lists that agent alone. The owner stays on only when an owner row says so, which the owner adds in the editor or an
agent sends in the set. Removing every row brings the default back.

**`save_task`, the API and the editor send the whole set, as tags do.** `contributors` takes an array of
`{kind: "owner"}` and `{kind: "agent", agent:, model:}`. Leaving it out keeps the rows as they are, and an empty
array clears them, which lists the owner again.

**The commit sync credits a commit once, when it first stores it.** `Record::Operations::StoreCommits` already sorts
the shas it knows from the new ones. For a new commit only, the record slice reads each `Closes #N` line and each
`Co-Authored-By` trailer, and hands the repo, the issue numbers and the agents to an operation the tasks slice exports
([ADR 0003][0003]). That operation finds each task by the GitHub issue URL in `task_sources.url`, the way
[ADR 0103][0103] finds a rule's tasks, and inserts with `ON CONFLICT DO NOTHING`. A commit the sync has seen is never
read again, so a contributor the owner removes stays off, as a removed tag does under [ADR 0077][0077].

**A trailer name maps to an agent by a fixed prefix in the record slice.** A name that starts with `Claude` credits
agent `claude-code`, and the rest of the name becomes the model: `Claude Opus 5.5` becomes `claude-opus-5-5`, lower
case with each run of other characters turned into a hyphen and `claude-` in front. A trailer whose name matches no
prefix, or names no model after it, credits nobody, so a human co-author or a bare `Claude` adds no row. The sync
reads the trailer key in any case, as git does. `/commit` writes `Co-Authored-By: Claude Opus 5.5` with
Anthropic's no-reply address (#621).

## Alternatives

**A jsonb column on `tasks`.** One column, no join. It lost because Postgres cannot hold each entry to the owner or
agent-and-model shape without a trigger, and every filter would read jsonb.

**Private tags such as `agent:claude-code`.** No new table. It lost on three counts. [ADR 0077][0077] tags only on
import, before any commit exists. A tag cannot keep an agent paired with its model. And [ADR 0065][0065] keeps tags as
labels, where a contributor records who acted.

**An enum for agents and models.** [ADR 0015][0015] types a closed set as an enum, but models change with each
release, and each would take a migration before the sync could credit it.

**Tables of agents and models.** Each row would point at curated lists. It lost because the lists need a screen to
keep, and the sync would have to create a row for each new model it meets.

**Store an owner row on every task.** The default would sit in the table, not in each read. It lost because no task
closed before #616 gets a row, so the read side needs the default anyway, and a stored row would keep the owner on a
task an agent did alone.

**Leave the agent out when the trailer does not name the tool.** It lost because filtering by agent would then miss
every task the sync credits.

## Consequences

Agents, the owner and the sync write one shape, and Postgres refuses any row outside it.

The default lives in every query that filters or lists contributors: the relation and both views. A new reader that
skips it shows a task with no rows as listing nobody.

The owner has to add themselves to share credit with an agent, and an agent that sends a set without reading the task
first drops an owner row it did not see.

A Claude commit made from another tool reads as `claude-code`. A new agent or a new trailer form takes a code change
in the record slice.

A commit stored before its task exists credits nobody, and nothing looks again. A commit rewritten after a push gets a
new sha and credits again, bringing back a contributor the owner removed.

Nothing records whether a row came from the editor, an agent or a commit, so no later change can tell them apart.
